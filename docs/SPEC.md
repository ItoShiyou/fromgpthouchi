# まちの余白：夜喫茶 ― アプリ仕様（モック v0.1）

> 誰かの日常の、ほんの少しだけ特別な時間を覗く。

このドキュメントは企画書を「実際のアプリ仕様」に落としたものです。
リポジトリの Flutter コードはこの仕様のモック実装で、企画書「25. 最初の試作品」の規模
（客 5 / 家具 10 / メニュー 6 / 出来事 5 / 放置 12 時間）で、スマホで触れる状態になっています。

検証したいことは 1 つだけです。

> **アプリを閉じて、翌日また開きたくなるか。**

---

## 1. 設計の柱

| 要素 | 役割 | 実装での扱い |
| --- | --- | --- |
| 売上 | ゲームを動かす燃料 | 家具・メニューを買うためだけに使う。売上ランキング等は無い |
| 家具 | 世界観を変えるもの | ステータス無し。**タグ**だけを持ち、組み合わせで「雰囲気」が生まれる |
| 客 | 収集対象 | 来店回数で名前・プロフィール・好物が少しずつわかる |
| 出来事 | 発見対象 | 日を跨いで少しずつ進む。説明しすぎない一文で記録される |
| ガチャ | 世界観を増やす課金装置 | 出るのは家具・小物・BGM・演出だけ。性能は変わらない |

「経営ゲームに見えて、実態は日常観察・収集ゲーム」。

```text
│   │   ├── ambience.dart       家具タグ → 雰囲気
│   │   ├── idle_engine.dart    放置計算（来店・売上・出来事）
```

## 3. 画面（MVP 10 枚＋α）

デザインの方針（参考ビジュアルに準拠）：

- **夜の紺地（星空）× クリーム色の紙パネル × 焦げ茶のボタン**。色は `core/brand/theme.dart` に集約
- **お店が常に基点**。下部のアイコン列（お客様・図鑑・家具・メニュー・くじ・ショップ）から
  紙のパネル（`PaperPage`）を開き、戻るとお店に帰る。タブは茶色の丸いピル（`PillTabs`）
- お店の画面は全面の一枚絵。上部に店の Lv・時刻・天気、所持金・チケット。客の頭上に会計バッジ、
  いちばん最近の客に吹き出し。床では店の猫が寝ている
- 客は似顔絵（髪型・服・差し色・眼鏡の組み合わせをコードで描画。未発見はシルエット）

「店の Lv」は来店・発見・収集から計算する**見た目の進み具合**で、売上や客の出現には影響しない。

### 1 回のプレイ（2 分程度）

```text
起動 → タイトル「はじめる」
     → 「おかえりなさい」（経過時間・売上・来店・新しいアイテム・特別な出来事の件数、はじめての客）
     → 特別な出来事を 1 つずつ（「窓際の二人」1/6 など）
     → 店の画面（席に最大 3 人。頭上に会計バッジ、吹き出し）
     → 客をタップ：ひとこと＋売上を回収（「この人のこと」で客詳細へ）
     → レジの残りを回収
     → 家具を買って置く／図鑑を見る
     → 閉じる
```

アプリを開いている間も 20 秒ごとに時間を精算し、新しい客が座ります。
営業中に出来事が起きた時は「特別な出来事」を、はじめての客は画面下に小さく通知します。

## 4. 放置計算

```text
elapsed          = now - lastSimulatedAt
effectiveElapsed = min(elapsed, 12h)
```

- 時間を **5 分の tick** に区切る。tick は絶対時刻で区切るので、
  **何回に分けて起動しても結果は同じ**（テストで保証）。
- 各 tick の境界時刻から `visitorSeed` / `eventSeed` を作り、その時刻の出来事を決める。
  天気は `weatherSeed`（日付 × 3 時間ブロック）で決まる。サーバー不要。
- 12 時間を超えた分は数えないだけで、**罰はない**。
  出来事の「◯日後」は実時間の営業日（朝 5 時区切り）で判定するので、
  何日も離れていても物語は先に進める状態になっている。
- 1 tick の処理:
  1. 閉店時間帯なら何もしない（夜喫茶は 24 時間営業の設定）
  2. 来店判定 `p = 0.17 × (雨なら 0.85) × (1 + 0.08 × 雰囲気の数)`
  3. 来店したら客を重み付きで抽選（通りすがり 2.5 ＋ 条件を満たす常連）
  4. 注文：好物がメニューにあれば 70% で好物、それ以外は出せるメニューから
  5. 1% で余白くじチケットを置いていく
  6. 出来事の判定（1 tick に最大 1 つ）
- 最新 3 人は「席に座っている客」として残し、それ以外の売上はレジへ。
- 1 営業日に 1 枚、開いたら余白くじチケットを配る（取り逃しても罰なし）。

### 客の出現重み

```text
weight = baseWeight
       × weatherBoost[天気]
       × Π ambienceBoost[成立している雰囲気]
       × (週末 ? weekendBoost : weekdayBoost)
       × (金曜 ? fridayBoost : 1)
       × (好物がメニューにある ? 1.3 : 1)
```

時間帯・天気が合わない客は 0。例：

| 客 | 時間帯 | 条件・傾向 |
| --- | --- | --- |
| 夜勤明けの看護師（朝いちばんの人） | 朝 | 落ち着いた店 ×1.6 |
| 新聞の男（窓際の人） | 夕方・夜 | 金曜 ×1.5（会社員）、昔ながらの店 ×1.6 |
| 参考書の高校生（制服の人） | 夕方・夜 | 雨 ×2（雨→学生が増える）、週末 ×0.4 |
| 犬を連れた大学生 | 朝〜夕方 | 晴れ・曇りのみ、週末 ×1.5 |
| 雨の日だけ来る人（傘の人） | 夜・深夜 | 雨・夕立・雪のみ、夜の店 ×2 |
| 古いカメラの老人 ※有料エピソード | 昼・夕方 | 雨・曇りのみ |

名前は来店 3 回目で判明、プロフィールは 1 / 3 / 6 回目で 1 行ずつ開く。
好物は実際に注文したところを見るまで「？？？」。

## 5. 雰囲気（家具＝世界観生成装置）

| 雰囲気 | 条件（タグ） | 影響の例 |
| --- | --- | --- |
| 落ち着いた店 | 緑 ＋ 暖色 ＋ 木 | 看護師・犬の大学生が来やすい／「夜勤明け」が進む |
| 夜の店 | ネオン・音楽・赤・月夜 のうち 3 つ | 傘の人が来やすい／「深夜のリクエスト」が始まる |
| 昔ながらの店 | レトロ ×2 | 新聞の男が来やすい |
| 本の匂いがする店 | 本 ＋ 暖色 | 高校生・新聞の男が来やすい／「窓際の二人」が進む |
| 雨宿りの店 | 雨 ＋ やわらか | 傘の人が来やすい |

模様替え画面で「あと：ネオン・音楽…」のように足りないタグを見せ、
**家具を買う理由＝見たい出来事がある** という動線にする。

## 6. 出来事（時間を跨ぐ小さな物語）

各物語は段階（StoryStep）の列で、段階ごとに条件を持つ。

- 条件：時間帯／天気／雰囲気／特定の客が来た tick／メニューがあるか／前の段階からの日数
- 同じ物語が同じ営業日に 2 段階進むことはない
- 図鑑では未発見の段階は「……」、次の段階にだけヒントを出す
- 最後まで見届けるとチケットや「店に残るもの」（例：赤い傘）がもらえる

| 物語 | 段階 | 鍵 |
| --- | --- | --- |
| 赤い傘 | 3 | 雨の夜に傘の人 → 翌日以降の朝昼 → 2 日後以降の晴れた夕方。完了で家具「赤い傘」 |
| 窓際の二人 | 6 | 新聞の男の来店ごと。3 段階目は「本の匂いがする店」、最後は晴れの日 |
| 夜勤明け | 3 | 看護師。曇りや雨の朝、最後は「落ち着いた店」 |
| 付箋の色 | 3 | 高校生。最後はクリームソーダが必要 |
| 深夜のリクエスト | 2 | 「夜の店」の深夜 |
| 雨の日の三人 ※有料 | 5 | カメラの老人と雨。完了で家具「三人の写真」 |

文章は説明しない。「あれ、この人たち何かあった？」と想像させる。

## 7. 課金（モック）

| 種類 | 商品 | 価格 |
| --- | --- | --- |
| 広告削除 | 広告なし（買い切り） | ¥680 |
| 家具の直接販売 | 月夜の窓セット／雨の日セット／レトロ喫茶セット | ¥220／¥320／¥680 |
| 余白くじ | チケット ×5／×11 | ¥160／¥320 |
| プレミアムエピソード | 雨の日の三人（客 1 人＋出来事 5 つ） | ¥320 |

モックでは IAP を呼ばず、確認ダイアログ後に `GameController.completePurchase()` を呼ぶ。
本実装では `in_app_purchase` の購入完了コールバックから同じメソッドを呼ぶ。

### 余白くじのルール

- 出るのは家具・小物・BGM・演出のみ（売上や来店数は変わらない）
- **排出率を画面に常時表示**（レアリティ別・アイテム別）
  - ふつう 70%（4 種）／めずらしい 25%（3 種）／とくべつ 5%（1 種）
- **天井**：10 回引くまでに未所持が出なければ、次の 1 回は必ず未所持
- 所持済みが出たら ¥500 の売上に換わる
- **「A+B+C を揃えたら報酬」は作らない**（コンプガチャに該当し得る設計を避ける）
- 「とくべつ」枠の月夜の窓は、セット販売で確実に買える
- 無料でもチケットは 1 日 1 枚＋客が置いていく分が手に入る

## 8. セーブデータ

モックは `shared_preferences` に JSON 1 本（`GameState`）。
本実装では以下に分割して Drift(SQLite) に置き、Supabase の `cloud_save` にバックアップする。

| ローカル（Drift） | 中身 |
| --- | --- |
| player_state | 売上・レジ・チケット・天井カウンタ・広告削除・最終精算時刻 |
| inventory | 所持アイテム・メニュー・購入済み商品・エピソード |
| furniture | スロットごとの配置、BGM・演出 |
| visitor_state | 客ごとの来店回数・初来店・最終来店・好物判明 |
| event_state | 物語ごとの進行・発見した段階と日時 |

| サーバー（Supabase） | 用途 |
| --- | --- |
| users / cloud_save | 機種変更・バックアップ |
| purchase_records | レシート検証・復元 |
| event_master / item_master / gacha_master | 配信で追加するコンテンツ |

乱数は 32bit 演算を JS でも同じ結果になるよう実装してあり、
**端末と Web で同じ時刻なら同じ客・同じ天気になる**（`test/seeded_random_test.dart`）。

## 9. このモックで見る指標（試遊時）

| 見たいこと | 見方 |
| --- | --- |
| 翌日また開くか（D1） | 試遊者の翌日起動率 |
| 1 回の滞在が 2 分前後に収まるか | 起動〜終了の時間 |
| 客の名前が判明するのが楽しいか | 客詳細を開いた回数 |
| 出来事の続きが気になるか | 図鑑「出来事」タブを開いた回数、ヒント後の模様替え |
| 家具を買う理由が「雰囲気」になっているか | 模様替え画面の滞在・購入順 |

本実装では Firebase Analytics でこれらのイベントを送る。

```bash
flutter pub get
```

実時間で待たなくても、**設定 → 試遊用** の「+1 / +3 / +8 / +13 時間」で
